Reward to Go and a Better Estimate

Starting from the policy gradient in part 2, the first easy improvement is causality, an action at time t cant affect rewards that already happened before t so we only sum the rewards from t onwards and that is called the reward to go Q̂i,t

∇θJ(θ) ≈ (1/N) Σi Σt ∇θ log πθ(ai,t | si,t) ( Σt′=tT r(si,t′, ai,t′) )

Q̂i,t is our estimate of the expected reward if we take ai,t in si,t but the issue is that it only comes from one trajectory, so it is the total reward we happened to get on that one run, if we could instead use the expected value ie take into account all the possible trajectories from that point and average them that would reduce the variance a lot coz averaging over more outcomes always lowers variance, and that expected value is exactly the true Q function

Q(st, at) = Σt′=tT Eπθ [ r(st′, at′) | st, at ]

What About the Baseline

We still want a baseline and in part 2 it was the average reward, now we can average Q values but averaging over what, the best thing to subtract is the average Q over the actions in that state which is just the value function V(st) = Eat ~ πθ[Q(st, at)]

Q minus V is called the advantage and it says how much better at is than the average action in that state, so the gradient pushes up actions that are better than average in that state and pushes down the ones that are worse

Aπ(st, at) = Qπ(st, at) − Vπ(st)
∇θJ(θ) ≈ (1/N) Σi Σt ∇θ log πθ(ai,t | si,t) Aπ(si,t, ai,t)

The better our estimate of A the lower the variance

Fitting the Value Function

So which one do we fit, Q, V or A, the trick is that Q is just the reward right now plus the value of wherever you land next

Qπ(st, at) ≈ r(st, at) + Vπ(st+1)
Aπ(st, at) ≈ r(st, at) + Vπ(st+1) − Vπ(st)

so we just fit Vπ(s) with a neural net coz it only depends on the state which makes it easier to learn and then everything else comes from it, fitting V is called policy evaluation and the objective itself is J(θ) = Es1 ~ p(s1)[Vπ(s1)] so if we can evaluate V we can evaluate the policy

Monte Carlo Evaluation

The simplest way to get V is monte carlo which is what policy gradient was already doing, just sum up the rewards you actually got from that state Vπ(st) ≈ Σt′=tT r(st′, at′) and ideally you would run many rollouts from the same state and average them but that needs you to reset the simulator to that exact state which you usually cant

So monte carlo estimates how good the experience was and policy gradient uses that to improve the policy

With a neural net it works out fine anyway coz the same function has to fit many samples from similar states so it naturally averages out the noise, not as good as many rollouts from one state but still pretty good, so the training data is the state paired with the reward to go and we do normal supervised regression

training data {(si,t, Σt′=tT r(si,t′, ai,t′))}     L(φ) = ½ Σi || V̂φπ(si) − yi ||2

Bootstrapping

We can do better, the ideal target is the expected reward to go which is r right now plus V of the next state, and we dont have the true V but we have our current fitted one so we just plug that in

yi,t ≈ r(si,t, ai,t) + V̂φπ(si,t+1)

This is called a bootstrapped estimate, it has lower variance coz it only uses one real reward and the rest comes from the network but it is biased coz the network is never exactly right

An Actor Critic Algorithm

Putting it together the actor is the policy and the critic is the value function that tells the actor how good its actions were

1. sample {si, ai} from πθ(a | s) ie run it on the robot
2. fit V̂φπ(s) to sampled reward sums
3. evaluate Âπ(si, ai) = r(si, ai) + V̂φπ(s′i) − V̂φπ(si)
4. ∇θJ(θ) ≈ Σi ∇θ log πθ(ai | si) Âπ(si, ai)
5. θ ← θ + α∇θJ(θ)

Discount Factors

If the episode is infinitely long V can just keep growing forever so we add a discount factor γ between 0 and 1 usually 0.99 and the target becomes yi,t ≈ r(si,t, ai,t) + γV̂φπ(si,t+1), the way to think about it is that at every step there is a 1 − γ chance you die and get no more reward, so rewards sooner are worth more than rewards later

For monte carlo policy gradients there are two ways to add it and they are not the same

option 1   (1/N) Σi Σt ∇θ log πθ(ai,t | si,t) ( Σt′=tT γt′−t r(si,t′, ai,t′) )
option 2   (1/N) Σi Σt γt−1 ∇θ log πθ(ai,t | si,t) ( Σt′=tT γt′−t r(si,t′, ai,t′) )

Option 2 is the mathematically correct one if you really believe in the dying story coz it also says that later decisions matter less ie later steps dont matter if you are already dead, but option 1 is what we actually use coz we usually want a policy that does well at every timestep not just early on, and the discount is really there as a variance reduction trick rather than as part of the true objective

Online Actor Critic and Architecture

With a critic we dont even need full trajectories we can update after every single step

1. take action a ~ πθ(a | s) and get (s, a, s′, r)
2. update V̂φπ using the target r + γV̂φπ(s′)
3. evaluate Âπ(s, a) = r(s, a) + γV̂φπ(s′) − V̂φπ(s)
4. ∇θJ(θ) ≈ ∇θ log πθ(a | s) Âπ(s, a)
5. θ ← θ + α∇θJ(θ)

For the networks you can have two separate ones, one for V̂ and one for π, which is simple and stable but they dont share any features, or one shared network with two heads which shares features but is harder to train coz the two losses pull on the same weights

The problem with steps 2 and 4 is that a batch of one sample is way too noisy, so it works best with a batch from parallel workers, synchronized parallel actor critic has all the workers collect a step and then update together and asynchronous has each worker update a shared θ whenever it is done which is faster but means some workers are using slightly old params

Critics as State Dependent Baselines

Comparing the two, actor critic with r + γV̂(s′) − V̂(s) has lower variance coz of the critic but it is not unbiased if the critic isnt perfect, policy gradient with a constant baseline has no bias but higher variance coz it is a single sample estimate

The middle ground is to use the critic only as the baseline and keep the real monte carlo reward to go

∇θJ(θ) ≈ (1/N) Σi Σt ∇θ log πθ(ai,t | si,t) ( ( Σt′=tT γt′−t r(si,t′, ai,t′) ) − V̂φπ(si,t) )

which has no bias coz any baseline that only depends on the state is fine, and lower variance coz the baseline is closer to the actual rewards than a single constant

N Step Returns and GAE

So the critic version ÂC has low variance but high bias if the value is wrong (and it always is) and the monte carlo version ÂMC has no bias but high variance, can we combine them to control the bias variance trade off

The idea is that the variance mostly comes from far in the future coz the further out you go the more the trajectories spread apart, so we use real rewards for the first n steps and then cut and let the critic handle the rest

Ânπ(st, at) = Σt′=tt+n γt′−t r(st′, at′) − V̂φπ(st) + γn V̂φπ(st+n)

You get more bias if you use a small n and more variance if you use a large n so we mostly prefer cutting earlier, and choosing n > 1 often works better than either extreme

But why pick just one n, generalized advantage estimation cuts everywhere at once and takes a weighted mix of all the n step returns with weights that fall off exponentially wn ∝ λn−1 which again prefers cutting earlier, and it simplifies really nicely

ÂGAEπ(st, at) = Σt′=t∞ (γλ)t′−t δt′     δt′ = r(st′, at′) + γV̂φπ(st′+1) − V̂φπ(st′)

So λ acts kind of like another discount, λ = 0 is the one step critic and λ = 1 is monte carlo, and this is also a nice way to see that the discount γ is itself a variance reduction knob, GAE is what PPO uses by default
