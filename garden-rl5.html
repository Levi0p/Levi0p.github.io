Policy Gradient as Policy Iteration

Turns out policy gradient is really just a soft version of policy iteration from part 4, instead of jumping straight to the argmax policy it nudges the policy towards actions with high advantage, and there is a neat identity that makes this exact, for J(θ) = Eτ ~ pθ(τ)[Σt γt r(st, at)] the improvement from old params θ to new params θ′ is

J(θ′) − J(θ) = Eτ ~ pθ′(τ) [ Σt γt Aπθ(st, at) ]

The proof is short, J(θ) is just the expected Vπθ(s0) and the starting state distribution doesnt depend on the policy so we can take that expectation under pθ′(τ) instead, then write V(s0) as a telescoping sum Σ γtV(st) − Σ γtV(st+1) and combine it with the reward sum and every term turns into r + γV(st+1) − V(st) which is the advantage

So the expectation is under the new policy but the advantage is under the old one, which is exactly what policy iteration does ie evaluate the old policy and pick a new one that does well under that evaluation

The Distribution Mismatch Problem

Using importance sampling on the actions we can rewrite it as

Σt Est ~ pθ′(st) [ Eat ~ πθ(at | st) [ (πθ′(at | st) / πθ(at | st)) γt Aπθ(st, at) ] ]

but the states still come from pθ′(st) which we cant sample from, so the question is can we just use pθ(st) instead, if we can then we get Ā(θ′) and we could just do θ′ ← argmaxθ′ Ā(θ′) and that would be the whole algorithm, plus if you take its gradient at θ = θ′ the ratio goes to 1 and you get exactly the normal policy gradient

Basically you have a huge annoyance in rl, to know how good a new policy is you need data from that new policy but you dont have that data yet coz you havent run the new policy, so to cheat and make it work we use old data we already have and adjust for the difference with importance sampling, the catch is that this cheat only works if the new policy doesnt change too wildly from the old one and if you change too much everything breaks, which is exactly why modern algos like PPO force the policy to update in small safe baby steps

Bounding the Distribution Change

The claim is that pθ(st) is close to pθ′(st) when πθ is close to πθ′, start with the simple case where πθ is deterministic and πθ′ takes a different action with probability at most ε, and this is literally the same setup as the behavioural cloning analysis in part 1

pθ′(st) = (1 − ε)t pθ(st) + (1 − (1 − ε)t) pmistake(st)
|pθ′(st) − pθ(st)| ≤ 2(1 − (1 − ε)t) ≤ 2εt

Not a great bound but a bound, for the general case where πθ is any distribution we say πθ′ is close if |πθ′(at | st) − πθ(at | st)| ≤ ε for all st, and a useful lemma says that if two distributions differ by ε in total then you can build a joint distribution where they agree with probability 1 − ε, so πθ′ takes a different action than πθ with probability at most ε and the same 2εt bound holds

Then for any function f the expectation under the new state distribution is at least the one under the old minus the error times the biggest possible value

Epθ′(st)[f(st)] ≥ Epθ(st)[f(st)] − 2εt maxst f(st)

so the real objective is at least Ā(θ′) minus Σt 2εtC where C is O(Trmax) or O(rmax / (1 − γ)), and maximizing Ā maximizes a lower bound on the thing we actually want, so

θ′ ← argmaxθ′ Ā(θ′)   such that   |πθ′(at | st) − πθ(at | st)| ≤ ε

and for small enough ε this is guaranteed to improve J(θ′) − J(θ)

KL Divergence and Enforcing the Constraint

KL divergence is a measure of how one probability distribution differs from a second reference one, in ml and rl it basically tells you the information lost or the distance between two distributions like how much a new policy or state distribution drifts away from the old one

DKL(p1(x) || p2(x)) = Ex ~ p1(x) [ log (p1(x) / p2(x)) ]

The total variation constraint above is awkward to work with but it is bounded by KL

|πθ′(at | st) − πθ(at | st)| ≤ √( ½ DKL(πθ′(at | st) || πθ(at | st)) )

so constraining KL also bounds the state marginal difference and KL has really convenient properties that make it much easier to approximate, so the problem becomes maximize Ā(θ′) such that DKL ≤ ε

One way to enforce that is to turn it into a Lagrangian

L(θ′, λ) = Ā(θ′) − λ ( DKL(πθ′(at | st) || πθ(at | st)) − ε )
1. maximize L(θ′, λ) wrt θ′
2. λ ← λ + α ( DKL(πθ′(at | st) || πθ(at | st)) − ε )

The intuition is raise λ if the constraint is violated too much and lower it otherwise and this is called dual gradient descent, PPO is basically a simpler cousin of this where you either add a KL penalty or just clip the ratio so the policy cant move too far

Natural Gradient, Properly This Time

Another way is to use a first order approximation, if we just take a small step then Ā(θ′) is basically linear so we maximize ∇θĀ(θ)T(θ′ − θ) such that the KL ≤ ε, and when you evaluate ∇θĀ at θ′ = θ the ratio cancels and it is exactly the normal policy gradient ∇θJ(θ)

So can we just use the gradient then, the problem is normal gradient ascent θ ← θ + α∇θJ(θ) actually solves the problem with the constraint ||θ − θ′||2 ≤ ε ie a circle in parameter space, which gives

θ′ = θ + √( ε / ||∇θJ(θ)||2 ) ∇θJ(θ)

but some params change the probabilities a lot more than others so a circle in parameter space is the wrong shape, the KL constraint to second order is DKL(πθ′ || πθ) ≈ ½ (θ′ − θ)T F (θ′ − θ) with F the Fisher information matrix so it is an ellipse, and solving with the ellipse gives the natural gradient

θ′ = θ + α F−1 ∇θJ(θ)     α = √( 2ε / (∇θJ(θ)T F ∇θJ(θ)) )

So to sum up, policy gradient is policy iteration, it optimizes the advantage under the new policy's state distribution, using the old state distribution optimizes a bound as long as the policies are close enough, which gives a constrained optimization problem, a first order approximation of the objective is gradient ascent and regular gradient ascent has the wrong constraint so we use the natural gradient and that is basically TRPO

Model Based RL and Planning

All of the above we did without needing the transitions ie p(st+1 | st, at) was assumed to be unknown but from now on we will start working with them, and often knowing the dynamics makes things a lot easier, like in games or easily modelled systems or simulated environments, and all of this is called model based rl

In the simplest version we know the transitions and based on that we pick actions, so it is choosing actions under perfect knowledge of the system dynamics and there isnt even a policy here, we just pick the best sequence of actions and this is called planning or trajectory optimization, like if there is a tiger the objective is literally

mina1, …, aT log p(eaten by tiger | a1, …, aT)

or more generally minimize total cost subject to the dynamics

mina1, …, aT Σt=1T c(st, at)   s.t.   st = f(st−1, at−1)

Open Loop vs Closed Loop

In the deterministic case the robot gets s1 from the world, thinks about the whole plan a1, …, aT in its head and then just executes it, and that is fine coz the world will do exactly what the model says

a1, …, aT = argmaxa1, …, aT Σt r(st, at)   s.t.   st+1 = f(st, at)

In the stochastic open loop case we do the same thing but maximize the expected reward given the action sequence, and this is very suboptimal coz we are picking the whole set of actions ahead of time based only on the initial state, but since p(st+1 | st, at) has uncertainty we may land in different states than predicted and the errors accumulate, like a plan for an exam where you commit to every answer before seeing the questions

Closed loop means the agent looks at the state at every step and acts on it at ~ π(at | st) which is what a policy does, open loop means it commits to a plan without looking at what happens, so we generally prefer closed loop over open loop and in practice planning methods get around it by replanning every step

Random Shooting and CEM

Abstract away the control part and just call the whole thing A = argmaxA J(A) where A is the sequence of actions and we dont care what J is, we can only evaluate it

Stochastic optimization in its simplest form is guess and check also called the random shooting method, so try a1, a2, a3 or a1, a4, a2 or a5, a1, a3 and check which is best through the simulator or model

1. pick A1, …, AN from some distribution eg uniform
2. choose Ai based on argmaxi J(Ai)

It is very simple to implement and very fast coz we are just brute forcing and it parallelizes perfectly but it isnt very good, CEM does the same thing but improves the sampling distribution each round so it focuses on the good region

1. sample A1, …, AN from p(A)
2. evaluate J(A1), …, J(AN)
3. pick the elites Ai1, …, AiM with the highest value where M < N
4. refit p(A) to the elites and repeat

Both have a very harsh dimensionality limit and only do open loop planning, but CEM with like a gaussian is actually a really strong baseline for small problems

Monte Carlo Tree Search

For discrete actions like in an Atari game we can build a tree where each branch is an action, but we cant search all the paths coz the tree grows exponentially so where do we search first, the intuition is choose nodes with the best reward but also prefer nodes we have rarely visited so we dont miss something good

1. find a leaf sl using TreePolicy(s1)
2. evaluate the leaf using DefaultPolicy(sl)
3. update all values in the tree between s1 and sl
repeat and then take the best action from s1

The UCT tree policy is if st isnt fully expanded try a new action, else pick the child with the best score

Score(st) = Q(st) / N(st) + 2C √( 2 ln N(st−1) / N(st) )

where Q is the total return through that node and N is the visit count, so the first part is the average return which is exploitation and the second part is big when a node has barely been visited compared to its parent which is exploration, DefaultPolicy is usually just a random rollout to the end

This is exactly what my Hex AlphaZero uses except AlphaZero swaps the random rollout for the value network and adds the policy network's prior to the exploration term so it searches the moves the network already likes first

Using Derivatives: LQR

If we can differentiate the dynamics we can write the whole thing as one big unconstrained problem just by plugging the dynamics into each other

minu1, …, uT c(x1, u1) + c(f(x1, u1), u2) + … + c(f(f(…)…), uT)

The usual story would be to just backprop through it and optimize with df/dx, df/du, dc/dx and dc/du (control people write x for state and u for action) but in practice it really helps to use a second order method, and the classic one is LQR where the dynamics are linear and the cost is quadratic

f(xt, ut) = Ft [xt ; ut] + ft     c(xt, ut) = ½ [xt ; ut]T Ct [xt ; ut] + [xt ; ut]T ct

The base case is to solve for uT only coz the last action only affects the last cost, so we write Q(xT, uT) as a quadratic, set its gradient wrt uT to zero and get

uT = KT xT + kT     KT = −CuT,uT−1 CuT,xT     kT = −CuT,uT−1 cuT

Since uT is fully decided by xT we can substitute it back in and get V(xT) = const + ½ xTT VT xT + xTT vT which is again quadratic, then uT−1 affects xT through the linear dynamics so plugging the linear dynamics into the quadratic V keeps everything quadratic in xT−1 and uT−1 and we can repeat the same trick all the way back to the start

backward recursion, for t = T to 1
Qt = Ct + FtT Vt+1 Ft    qt = ct + FtT Vt+1 ft + FtT vt+1
Kt = −Qut,ut−1 Qut,xt    kt = −Qut,ut−1 qut
Vt = Qxt,xt + Qxt,utKt + KtTQut,xt + KtTQut,utKt
vt = qxt + Qxt,utkt + KtTqut + KtTQut,utkt

and then since we know x1 we do a forward recursion, for t = 1 to T set ut = Ktxt + kt and xt+1 = f(xt, ut), and that gives the actual numbers for the whole optimal trajectory

Stochastic Dynamics and Iterative LQR

If the dynamics are gaussian p(xt+1 | xt, ut) = N(Ft[xt ; ut] + ft, Σt) the solution is still ut = Ktxt + kt, xt isnt deterministic anymore but it is gaussian and coz gaussians are symmetric the Σt just drops out so there is no change to the algorithm, and the nice part is Ktxt is closed loop so it reacts to whatever state you actually end up in

For nonlinear systems we use iterative LQR, take the current trajectory x̂t, ût and do a Taylor expansion around it, first order for the dynamics and second order for the cost, which gives a linear quadratic problem in δxt = xt − x̂t and δut = ut − ût that we can just run LQR on

until convergence
Ft = ∇xt,ut f(x̂t, ût)    ct = ∇xt,ut c(x̂t, ût)    Ct = ∇2xt,ut c(x̂t, ût)
run the LQR backward pass on δxt and δut
run the forward pass with the real dynamics and ut = Kt(xt − x̂t) + αkt + ût
update x̂t and ût from the forward pass

Why does this work, compare it to Newton's method for minx g(x) where every step you compute the gradient g and Hessian H at x̂ and jump to the min of the quadratic approximation ½(x − x̂)TH(x − x̂) + gT(x − x̂), iLQR is the same idea of locally approximating a complex nonlinear function with a Taylor expansion and in fact it is an approximation of Newton's method for the whole unrolled problem, and if you also keep the second order terms of the dynamics you get exactly Newton's method which is called differential dynamic programming (DDP)

The one catch is that jumping straight to the min of the quadratic can overshoot when the real function isnt quadratic far away, so that α in the forward pass is a line search ie start with α = 1 and keep shrinking it until the cost actually improves
